# 使用流程（三级目录 · 角色 · 一轮巡检）

> 这份是给人和 AI 共用的口径。装法看 [`QUICKSTART.zh-CN.md`](QUICKSTART.zh-CN.md)。

## 一、三级目录

看板按 **仓库 → 目录 → 会话** 折叠，三个层级各管一件事：

| 层 | 是什么 | 谁在用 |
|---|---|---|
| **仓库** | `repos.json` 里的一行：别名、路径、主分支、显示名 | 决定这一组挂在哪个仓 |
| **长期目录** | 主检出（只读）、`test`、`develop`、`release` | 看代码、合并；每个任务可以挂自己的会话，但同一份磁盘只能同时干一件事 |
| **执行目录** | 本次任务的基线（`feature/…` / `hotfix/…`）和并行分支 | 真正改代码的地方 |
| **会话** | 挂在某一格里的 agent 会话 | 协调、主线、辅助 |

规则：

- 加一个仓库，必须带长期四格；执行基线没定就写「未指定」。**加项目不建 worktree。**
- 一个工作区钉一条分支，不在同一目录里切来切去。
- 主检出只读：只允许 `fetch` / `log` / `show` / `diff`。
- 合并只在对应的长期目录里做；改代码走执行目录。
- 同一份长期目录可以挂在多件任务上，但同一时刻只让一件任务在里面改或合并。

## 二、角色

| 角色 | 谁 | 只做什么 |
|---|---|---|
| **协调** | 主代理「信箱调度」 | 读协调介质、查状态、派单、收口；不读代码、不查库、不改业务 |
| **主线** | 挂在执行目录的会话（`role: main`） | 推进这件任务，持有完整上下文 |
| **辅助** | 派生会话（`role: helper`） | 查代码、核事实、小问询；用完就结束 |

子代理分工：

- **看板操作**：建任务、加项目、开会话。只跑 `taskhub`。
- **worktree-builder**：建 worktree 并顺手建会话。一次一个仓库。
- **cli-operator**（可选）：飞书、云效、SLS、数据库只读、Apifox。没装就在派单里报缺。

每个 worktree 最多三个会话：一条主线 + 至多两个辅助。超过就先报「哪几个该合并或结束」。

## 三、写域

一件任务的进度目录（`~/.task-hub/tasks/<id>/`）里：

| 文件 | 谁写 | 内容 |
|---|---|---|
| `HEAD.md` | 协调 | 当下状态、正在做、卡在哪、下一步；每轮覆盖 |
| `SUMMARY.md` | 协调 | 只写有出处的结论，一条 ≤ 6 行 |
| `DECISIONS.md` | 协调 | 定过就不动的口径 |
| `RUNBOOK.md` | 任何会话可补 | 怎么跑起来：命令 + 预期结果，带日期与出处 |
| `progress/progress-<id后6位>.md` | **各会话只写自己那份** | 本轮做了什么、证据、卡点、下一步 |
| `deliverables/` | 各会话 | 方案、提测、工单这类成品 |
| `archive/` | 协调 | 归档区，只读 |

别人那份 progress 只读，不代改、不代压。

## 四、一轮巡检（协调会话）

1. **定范围**：点名就只做那件，说「全部」就做全板。
2. **取事实**：读 `tasks.json`；成员状态用 `session.status` 查。
3. **读变化**：`HEAD.md` → `SUMMARY.md` → 只读有变化的 progress 最后三段。
4. **分四桶**：在跑 / 可推进 / 等你定 / 已完成（外加未开工、超限）。
5. **发催办**：只对可推进和未开工。四要素（目标、范围、验收、约束）不全就不发。
6. **补 RUNBOOK**：本轮第一次跑通的动作才写，没跑通不编。
7. **汇总**：有出处的结论进 `SUMMARY.md`；变的写回盘面。
8. **落记录**：`.dispatch.json` 记 `lastRun` 与本轮 `sent`，下一轮用它防重复。

派单纪律：

- 正文首行 `【回话】`，并且 `session.send` 带 `returnResult: true`；缺一个回执就回不来。
- 回执固定四行：回执 / 证据 / 卡点 / 下一步，作为最后一条消息发出。
- 目标会话 `busy` 时不塞第二封：等下一轮，或派生一个新会话接小活。
- 成员不自己向用户弹问题；要拍板的写进回执卡点，由协调统一问。

## 五、停点

单独确认：删文件、force、非查询 SQL、合并代码。

- `test` 分支合并可以按项目规则自己做。
- commit 与 push 是同一次确认，确认后连着做；merge 另外确认。
- 批准合并不等于批准提交；一次只做确认过的那一步。
- 已经批准的方案不重复问。

## 六、不做什么

- 不向别的会话自动发消息；发信永远是明确的一次动作。
- 不在讨论没选中时派会话或改文件。
- 不从 `test` / `develop` / `dev` / `release` 起分支。
- 不手改 `tasks.json` 的 `board`；建任务、加项目、开会话都走 `taskhub`。
- 不把「已跑通」当结论；对不上 file:line、命令输出或 SHA 就写未覆盖项。
