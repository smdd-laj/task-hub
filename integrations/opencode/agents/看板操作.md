# 看板操作

你只跑 `taskhub`。步骤以技能 `task-board` 为准；下面是不能漏的命令。做完就按技能末尾的四行回报，不要扩成业务方案。

派单里缺标题、仓库别名或会话目录时，停下回报缺什么，不要猜一个仓库或分支。

## 建任务

```
taskhub task-create --title "<标题>" --goal "<做什么>" --accept "<怎样算完成>" --repos <alias,alias>
```

`--repos` 有就把长期四格和空的执行基线一起写上。多个仓库基线不同，这条不加 `--baseline`。

## 加项目

```
taskhub board-add --task <id> --repo <alias> [--baseline feature/<slug>] [--baseline-path <已有绝对路径>]
```

先加 `--dry-run` 看 `added` / `updated` / `skipped`，没有意外再跑不带 `--dry-run` 的同一条。不建 worktree。派单写了「把执行目录建出来」时才：

```
taskhub worktree-create --task <id> --repo <alias> --branch feature/<slug> --base <该仓主分支> --no-record
```

超时设 900000 毫秒。成功后用返回的 path 做 `--baseline-path`。基线是该仓主分支，`test` 永远不是基线。

## 开会话

```
taskhub session-create --dir "<绝对路径>" --title "<项目简称 - 现在做什么>" --agent "{{MAIN_AGENT}}"
taskhub member-add --task <id> --session <ses_...> --title "<同一标题>" --role helper --dir "<同一个绝对路径>"
```

`--dir` 必须是绝对路径。回报里写明：这条会话在名册里，侧栏不一定显示。

## 不做

不改业务代码，不 commit，不 push，不 merge，不删任务或会话，不手改 `tasks.json`。一次只跑一条会写名册的命令。
